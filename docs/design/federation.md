# 经验包与串联（federation，最小实现）

## 想解决什么

一个坑踩过一次就够了。但经验现在锁在单机的 `memory.json` / `compress.json` 里，
换台机器、换个人就重新踩。经验包把这些**已经人审过的结论**打成纯 JSON，通过文件交换。

## 包里有什么 / 没有什么

| 有 | 没有 |
|---|---|
| 压缩块（区间 + 人写的摘要 + KEEP 原文） | 原始会话、完整对话日志 |
| 记忆（事实 / 反模式 / 片段，已过 `redact()`） | 密钥、邮箱、卡号（导入前已脱敏） |
| 技能的名字 + 触发语 | 技能正文（各机版本不同，正文会漂） |

格式（`packages/core/src/federation/bundle.ts`）：

```json
{ "format": "oml-experience", "version": 1, "from": "host-a",
  "createdAt": "2026-11-15T…", "blocks": [], "memories": [], "skills": [] }
```

上限：块 500 / 记忆 200 / 技能 300。超限整包拒绝——半个经验比没有更危险。

## 合并规则（本地优先）

1. 同 `id` 且摘要相同 → 跳过（重复）。
2. 同 `id` 但摘要不同 → **保留本地**，计 `skipped`，冲突留给人看。
3. 记忆按 `jaccard ≥ 0.75` 去重；导入条目改 `X<n>` 前缀、`hits` 归零（不是本机踩出来的）。
4. 技能同名只留本地描述。

## 命令

```bash
omo share export [--out <文件>] [--from <名字>]
omo share import <文件> [--dry-run]
```

`import` 会先打印人读摘要（`renderBundle`），再合并；`--dry-run` 只看不写。

## 传输：本模块零网络

包是普通文件，怎么送是调用方的事：U 盘、git、内网盘、IM 附件都行。
要联网的话，**同一个格式**可以直接 POST 到某个端点——但服务端不在本仓，
也不在路线图上，理由是：没有服务端就不会有第二个状态源，也不会有遥测。

## 与「组队」的关系

- 队列内：`omo_task action=team`（团队模板 + 工具/MCP 约束）负责**同机协作**；
- 队列间：经验包负责**跨机/跨人**的经验流动。
两者不共用状态机，也不互相依赖——一个是并发，一个是记忆。
