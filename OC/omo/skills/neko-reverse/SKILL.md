# Neko × 逆向工程（按需骨架）

> **定位：按需专业工具，不是 OML 内置能力。** 本技能只给方法论骨架与发现指引。
> 逆向依赖专门的静态/动态分析工具与领域知识，OML 不内置、不假装具备。
> 纪律：只在合法授权范围内使用（自己系统、有许可的目标、CTF、授权渗透）；不碰未授权目标。

## 0. 何时用 / 何时不用
- 用：用户明确要逆向某程序/协议/固件，且能说明来源与授权；或调试无源码的崩溃/行为。
- 不用：普通开发任务、有源码的问题、纯配置问题。
- 先问清：目标平台（x86/ARM/固件/APK/协议）、是否有源码/符号、授权情况、要产出什么（行为说明 / 数据结构 / patch / 报告）。**授权不明直接停下问 owner。**

## 1. 方法论骨架（分层的常识流程，不是工具教程）
1. **定界**：确认目标与授权，记录版本/哈希/来源，隔离环境（沙箱/虚拟机）运行，不污染宿主。
2. **静态**：文件类型/架构/加壳识别 → 符号/字符串/导入表 → 控制流与关键函数定位（材料里的 REA 指这类静态分析助手）。
3. **动态**：调试器下断点、跟踪调用与数据流、抓包（协议类）→ 观察运行时行为（材料里的 Craft anything 指这类通用分析助手）。
4. **还原**：把发现写成结构化结论——函数语义 / 数据结构 / 协议格式 / 关键常量，逐条标注证据（地址 / 抓包 / 反汇编片段）。
5. **验证**：用还原的结论预测行为并实测复核；结论须可复现，不靠单次观察。
6. **产出**：报告（发现 + 证据 + 复现步骤），交 owner；任何 patch/绕过只在授权范围内、由 owner 决定使用。

## 2. 发现指引（工具不在 OML 内，按需找）
- 先查本机已装技能：`omo_knowledge action=skill query="逆向 逆向工程 reverse 二进制 调试 协议"`。
- 再查 MCP：`omo_admin action=mcp op=show` + `omo_mcp` 的 `suggestMcp`（关键词：reverse/debug/disasm/frida/ghidra）。
- 需要 REA / Craft anything 或专用工具时：向 owner 报告缺口与用途，由 owner 决定是否安装；装完再按第 1 步走。**绝不静默下载/安装或运行未授权目标。**
- 逆向常在隔离目录做：用 `neko-pty` 技能开受控 PTY 会话，产物落 owner 指定目录。

## 3. 红线
- 授权不明的目标不碰；用途不明的 patch/绕过不做。
- 不联网下载工具/样本除非 owner 每次授权；不在宿主直接跑可疑二进制。
- 结论带证据、可复现；不把猜测当结论。
- 工具「未装」就说未装，不用占位内容假装跑通。
